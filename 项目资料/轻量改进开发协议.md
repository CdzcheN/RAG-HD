# MiniCheck 轻量改进 v0：有效证据重评分

日期：2026-11-05；在特征重评分和训练前固定本方案。输入批次为用户确认后的 `rag_challenge_20261104_v4`。本批全部标签和案例已经用于开发，因此后续内部划分只是探索性实验，不能冒充未见过的最终测试集。

## 已确认的出发点

120 条、60 个来源组的标签已确认：71 supported、9 unsupported、1 contradicted、5 outdated、34 undetermined。34 条含 21 条拒答、13 条事实歧义，保持原样。两种基线共同评估 86 条，幻觉正类 15 条：自评 AUC 0.629577、AP 0.374612；原始 MiniCheck AUC 0.712676、AP 0.533145。

以先前不看检测分数的构造复核结果定义敏感性子集：仅保留 finding=basic 的完整配对，共 36 组、72 条，59 条有标签（6 个正类）。自评 AUC 0.638365，MiniCheck 0.751572。其他组不从全量结果中删除，不能仅展示更有利的子集。

实际漏检动机：第 98 条回答采用失效的 John Knox，原始 MiniCheck 风险约 0.0288；第 100 条回答采用失效年份 1956，风险约 0.0350；第 86 条旧姓名 Franz Boas 风险约 0.0618。与“任一块支持即可”的聚合遇到旧/新共存时可能忽略有效性这一解释一致，但仍需用干预后重评分验证，不能仅凭案例确立因果。

## 第一版方法与范围

原始 MiniCheck 不改权重、代码与历史分数。新增“有效证据 MiniCheck”对照：根据**实际可见问题与证据头**中的显式规则选择资料，再用相同 MiniCheck 和回答句子聚合方式评分。

- 来源规则：问题明确声明 primary 优先且 secondary 不可覆盖时，仅保留 primary 的全部段落，完整保留多跳证据。
- 时间规则：问题明确给 Query date 与有效区间规则时，仅保留 valid_from ≤ query_date ≤ valid_until 的段落。无日期标注的干扰不视为已验证有效来源。
- 未识别规则或日期格式不合法时保留原始证据并记录回退。明确适用规则但没有可用有效证据时，记录 no_effective_evidence，风险为 1；拒答仍单列。
- 选择器不接收标签、参考答案、金标支撑、构造类型或注入位置。主体内容中伪装的 source_tier 文本不作为来源元数据。

再实现 StandardScaler + LogisticRegression，固定 C=1、class_weight=balanced、solver=liblinear，不搜索超参数。特征分四组：

1. 原始 MiniCheck 风险。
2. 原始可见资料中的问题词覆盖、回答词覆盖、回答数字覆盖，作为检索/回答词汇充分性的轻量代理；不将金标召回率用作特征。
3. 公开来源规则下的重评分差、只出现在被排除证据中的回答词比例、排除比例。
4. 公开时间规则下的重评分差、只在失效资料出现的回答词/数字比例、排除比例。

词汇不重合不等于事实矛盾；这些量只作为学习特征，不单独生成真值。本轮没有实现事实矛盾模型、独立语义编码器或成对排序损失，不能把“不支持”冒充“矛盾概率”。

## 对照、划分与阈值

固定对照：自评、原始 MiniCheck、有效证据 MiniCheck、原始风险单特征逻辑回归、全部特征逻辑回归，以及去词汇、去来源、去时间三组消融。暂不根据本轮结果反复替换特征或改 C。

使用预定种子 13、42、2026：先对全部 60 个来源组排序，再用 NumPy default_rng(seed) 打乱，按 36/12/12 个组划分开发训练/验证/内部测试。包括拒答与未确定标签的全部组先划分，再在各部分取共同可评分且有标签样本；不为平衡正类重抽种子。正常/挑战对始终同组。

标准化与逻辑回归只在训练部分拟合；每种方法的阈值只在对应验证部分按 Macro-F1 选择，平分时取最靠近 0.5，再取较小值。验证不足两类时回退 0.5 并明确记录。AUC/AP 不依赖该阈值。报告 Precision、Recall、Macro/Micro-F1、混淆矩阵和每个集合的样本/正类数。

三个种子复用同一生成、原始检测和新增重评分缓存。报告逐种子值、均值和样本标准差；内部测试还报告按来源组重采样的配对 AUC 差区间。此处正类很少、各划分重叠且已经用于方法开发，不做“达到显著提升”或最终验收结论；正式阶段需要修正构造并隔离新来源和模板。

## 研究定位与文献边界

这是一版针对实际错误的工程改进原型，不预先宣称研究创新。MiniCheck 的原始任务与训练方法见 [Tang 等，EMNLP 2024](https://aclanthology.org/2024.emnlp-main.499/)。时间信息用于证据排序与核查已有相关工作：[Time-Aware Evidence Ranking for Fact-Checking](https://arxiv.org/abs/2009.06402) 研究了基于时间的证据排序；[Implicit Temporal Reasoning for Evidence-Based Fact-Checking](https://aclanthology.org/2023.findings-eacl.13/) 研究了时间轴信息对核查分类器的影响。因此“考虑时间”或“过滤旧证据”本身不能声称首次。当前对照将检查具体的公开规则解析、MiniCheck 重评分及轻量融合是否适合本项目，创新性仍待更系统文献比较和独立实验。

当前解析器依赖本批显式元数据和规则表达，容易受合成模板影响；它不会从任意自然语言自动推断时间或来源可信度。正式实验应更换部分规则表达和版本格式，并在自然检索资料上验证。不能把公开构造模板上的结果直接推广到自然 RAG。

## 运行与产物

```bash
NLTK_DATA="$HOME/nltk_data" HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  .venv/bin/python scripts/extract_valid_evidence.py \
  --run-dir outputs/rag_challenge_20261104_v4 \
  --output-dir outputs/rag_improvement_dev_20261105_v1

.venv/bin/python scripts/train_lightweight.py \
  --run-dir outputs/rag_challenge_20261104_v4 \
  --output-dir outputs/rag_improvement_dev_20261105_v1
```

新增检测分数、特征、各组划分、训练模型、系数、验证阈值、逐条预测与资源记录单独保存，不覆盖原始 MiniCheck。详细数据与模型不提交 Git，归档摘要、版本及校验值。新增依赖为零；本轮只额外运行需要过滤证据的 MiniCheck，不重复生成回答。
