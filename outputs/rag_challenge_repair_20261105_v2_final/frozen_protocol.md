# 挑战构造修正版 v2：30 组小批检查

日期：2026-11-05。此次只推进构造修复和小批检查，不扩大到正式≥300条挑战，不把本批叫作最终独立测试。生成模型、原始 MiniCheck 以及已固定的 v0 有效证据筛选器均不改动。

## 修复内容

1. **题干必须有来源支撑。** 对有明确依据的省略进行显式改写，保留原题、改写和理由；无法确认的候选暂不使用。例如把 Imperial 的全校员工数问法改成“2014 REF 提交的员工数”，把 St. John's 的小学数改为原文支持的三类学校总数。Searby 方位倒置、天气台覆盖多个县却指定单一县等候选在文本检查中被排除，未读取模型分数。
2. **只改已核对的文字区间。** 每个编辑保存字段、起止位置、原文、新文和语义角色。拒绝过期、重叠或未覆盖已声明实体提及的编辑。人物标题、正式全名、姓氏和作品名称分开处理，避免把电视节目《Dr. Phil》也误改成人名。
3. **数量与约束同步。** 用 Decimal 保留逗号、百分号和小数位，处理进位、0—100%和声明的上下界。Nigeria 城市比例变化时，农村比例同步更新，使两者仍为100%；Libby 城市人口约束在县人口以内。未识别的数值关系不能声称已自动验证。
4. **自动时间扰动限于统计记录更正。** 不自动更改出生、死亡或公司成立年份。旧版 Activision 的“1983成立但1980已有产品”作为拒绝此类修改的回归例。此小批保留原观察日期，仅对同一历史统计的资料记载作合成更正；不声称是真实世界最新统计。
5. **检索失败移除全部金标支撑。** 避免仅删除一篇后，另一篇仍直接给出答案或职业线索。再按完整数量词/答案别名检查剩余正文和标题，且补足干扰材料，使正常与挑战均为5篇。此规则也不能保证消除所有隐式推导，生成后仍按实际回答复核。
6. **来源隔离处理编码别名。** 新样本及干扰材料都排除旧20条和120条中出现的可见来源以及金标来源。除旧来源ID外，还统一URL编码、HTML实体、Unicode、下划线、大小写及空白，避免同一标题的不同写法漏过检查。新目标来源不作为其他基础问题的干扰证据。

## 小批范围和人工判断边界

从同一固定版本 SQuAD/HotpotQA train 的种子20260918前4000条候选中，助手逐条核对来源文本后固定30份规格，每类每数据集5题。规格文件为 `configs/challenge_repair_specs.json`，内容包括ID、明确题干、来源片段区间、数量角色与已核对的约束，不含模型分数。

本批只覆盖数量槽位：检索失败10组、来源冲突10组、统计资料过时10组。人物别名的修复另外在旧第51、56、58组上构造前后对照，并非宣称新30组已覆盖所有人物、任意自然语言或时间推理。问题支撑、实体提及表和数值关系仍需要来源文本核对；这些修复不是自动语义真值判定器。

旧批次输入、生成、自评、MiniCheck及已确认标签全部保留，修正后的问题或资料不回填旧回答。本批采用明确的受控完整支撑条件和固定新来源干扰库，仍不等于完整维基自然检索评测。原型正常条件不会自动标为 supported，挑战不会自动标为幻觉。

## 复核与运行

运行配置：`configs/rag_challenge_repair.yaml`。目录：`outputs/rag_challenge_repair_20261105_v2_final/`。

- `construction_review.csv`：30组修正构造及助手检查理由，中文展示，不放哈希等技术列。
- `修正前后对照.csv`：7个旧问题/别名/时间约束修复例，未重新评估旧预测。
- `prepared.jsonl`、`data_manifest.json`、`construction_validation.json`：程序内部输入、版本及校验材料。
- 推理结束后生成 `review_readable.csv`，60条实际回答仍需标签复核，不用构造规则替代真实标签。

```bash
bash scripts/run_rag_challenges.sh \
  outputs/rag_challenge_repair_20261105_v2_final \
  configs/rag_challenge_repair.yaml

tail -n 30 -f outputs/rag_challenge_repair_20261105_v2_final/logs/pipeline.log
```

先做资源探测，再按生成/自评、MiniCheck、评估分阶段运行。仍记录12 GB限制、拒答、输出截断和解析失败，不为制造正类强迫作答。新增构造之后已生成回答的运行目录禁止再准备输入，避免旧缓存与新构造混用。

本轮38项CPU检查通过，其中包括完整多跳删除、人物别名与作品名称分离、重叠编辑拒绝、百分比进位/范围、联动百分比、事件年份禁用及编码标题隔离。结构检查与助手文本核验不替代后续用户检查，更不证明 v0 在新来源或新规则表达上泛化；正式隔离数据与未见表达的测试仍待后续推进。
