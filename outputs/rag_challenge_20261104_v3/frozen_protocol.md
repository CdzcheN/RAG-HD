# 三类挑战原型协议 v1

冻结日期：2026-11-04，首次配对生成前。配置 `configs/rag_challenge.yaml`，构造版本 `controlled-challenge-v1`。此协议用于开发原型，不用于最终测试集性能结论；后续变化新建版本和运行目录，不覆盖已有预测。

## 已确认的标签与评估规则

用户已检查并确认上一批 20 条助手预填结果，来源如实记录为“助手草稿经用户确认”，不是独立双人标注。15 条可评估事实回答、2 条证据语义歧义、3 条拒答。歧义不强制赋正负类，不为提高指标修改已确认标签。独立双人标注和正式抽检仍留待后续实验。

冻结下列约定：supported 要求全部实质性事实受到可见且有效证据支持；unsupported 是缺乏依据；contradicted 要求明确反证；outdated 要求明确可见的时间失效或更新关系。原型中不从 British 推断排他国籍，不将混合时期的含糊问法自动定性。题干可以限定任务，但题干预设、参考答案及隐藏支撑不能补足证据。答案正确性与证据支持分别保存。

拒答排除主事实幻觉 AUC，同时报告拒答率、事实回答覆盖率和有答案时过度拒答的案例。人工确认的 undetermined 排除 AUC，保留数量和理由。主比较使用有可靠标签且两种方法均有有限分数的共同集合，幻觉正类为 unsupported、contradicted、outdated。开发阶段不调阈值。未有可靠标签的配对批次不报告检测效果。

## 数据、选择与正常条件

继续使用此前固定版本的 SQuAD / HotpotQA train，各取种子 20260918 下 ID 哈希最小的 1,000 条；语料取这些问题上下文的并集。候选按独立 `challenge-base` 哈希排序，各挑战类型取 SQuAD 和 HotpotQA 各 10 题，共 60 个基础问题、120 条配对输入。排除上一批复核样本的原问题和金标来源文档，所选基础问题也不共享金标来源；所有变体继承同组。

选择依据仅包括文本可构造性和预算：短显式参考值、支持文档不超过 2 篇、每篇不超过 220 词、目标未被题干直接给出、删除后没有参考别名残留，以及替换值类型等。记录所有拒绝原因；不加载生成模型或检测器参与选择。类型过滤不是语义标注的替代，构造质量与生成后标签仍待逐条检查。

正常版为**受控完整支撑条件**：固定 BM25 检索后，用金标支撑文档补全证据，再加入不含参考别名的 BM25 干扰。保留原始检索排名与分数，明确记录补全操作。这适合成对分析证据扰动，不等于自然 Top-K 检索结果或完整维基开放域评测。当前来源分组针对基础问题的金标来源，不把共享检索库干扰段落当作不同的私有训练样本；正式划分仍需审查来源及替换模板泄漏。

## 三种可见干预

1. 检索失败：单跳删除支撑段落，多跳删除包含目标答案的关键一跳，保留其他支撑或干扰；若剩余内容包含参考别名，拒绝该构造。保存删除前后证据。此检查不保证已消除所有间接可推导支持，因此不能自动赋 unsupported。
2. 证据冲突：问题公开声明受控资料情境及 primary 优先于 secondary 的规则。正常版包含内容一致的两个来源，挑战版仅替换 secondary 中的目标值，primary 保留。来源规则和标记在三个方法的输入中一致可见；不显示“正确/错误”标注。确定性平衡来源先后顺序，两个配对成员保持同一顺序。
3. 答案过时：问题公开查询时间 2025-06-01。新版有效区间为 2025-01-01 至 2025-12-31，明确替代旧版；旧版有效至 2024-12-31。正常版含两份一致的有效记录，挑战版把其中一份换为已失效的旧记录，新版仍可见。查询时间、新值及来源排序在配对中一致。旧值只有在实际回答采用且与可见更新关系冲突时才考虑 outdated。

冲突和时间情境明确声明是实验构造，不冒充真实世界当前事实。日期等原本不可变事实的版本差异表示资料更正；本原型不能据此声称评测了现实新闻变化或自然时效问题。数据提交 SHA 不充当事实生效时间。

替换规则保留数字格式与单位，年份默认偏移 4 年；日期只修改年份并避开非闰世纪。人物仅使用符合姓名形式的多词值，并排除机构及代词短语；地名按题干的 city/country/state/town/village 槽位选取候选，国家名和国籍形容词不混用。该启发式仍有适用边界，不预先声称所有替换均通过语义人工验收。替换值进入私有构造记录；构造类别、参考值、删除位置不输入检测器。

## 推理、验收与下一步

固定此前已验收的 Qwen2.5-3B-Instruct NF4 与 MiniCheck 权重及提示词，单卡分阶段加载，共用相同实际问题、可见证据及生成回答。每阶段记录耗时、输入长度、输出截断、解析失败与显存；首先对本批最短/最长输入及 4,096 token 压力输入做探测，再执行 120 条。

所有生成结果保留，包括拒答和未遵守公开规则的回答。构造不生成回答标签，未复核前评价状态仍是待复核；不根据风险分数筛选或调整数据。完成后输出简明人工复核材料和构造质量检查表，再确定 P3.2 的错误类型与首批轻量特征。

早期 v1/v2 准备目录仅用于发现替换类型错误，未执行模型推理；修正后固定使用 `outputs/rag_challenge_20261104_v3/`。不存在按模型效果挑选版本的行为。

后台运行时，可查看 `outputs/rag_challenge_20261104_v3/logs/pipeline.log`；各阶段另有 probe/generate/score/evaluate 日志。`status.json` 是当前阶段，`pipeline_exit.json` 出现后记录流水线退出码。成功完成推理仍需标签复核，不应与标签验收完成混淆。
